# 总览与验证记录

## 一、用途

运行时阶段的 `总览.md` 和 `验证记录.md` 要保持紧凑、清楚、归属明确。

本 reference 就是运行时阶段这两个文件的唯一权威骨架。

## 二、视觉规则

统一使用纯 Markdown 和少量状态标记：

- `✅ 已确认`
- `🟡 待确认`
- `⛔ 阻塞`
- `🔍 待验证`
- `➡️ 下一步`

同时保留规范状态值，例如 `🟡 待确认（部分完成）`。

## 三、落盘路径

默认写到当前任务工作目录：

```text
reverse-records/
├─ 总览.md
├─ 请求链路.md
├─ 运行态清单.md
├─ 恢复记录.md
└─ 验证记录.md
```

## 六、归属规则

- `总览.md` 负责当前阶段、已确认、待确认、阻塞风险、待验证和下一步
- `运行态清单.md` 负责清单、纯算迁移前检查、可移除项和当前链路所需运行时事实
- `验证记录.md` 在补项开关、状态闭合、路线选择或首个分叉点需要证明时开始记录
- `验证记录.md` 可以由 `运行时` 提前启动，但归属阶段和完成门禁仍然属于 `验证`
- 只要路线依赖生命周期或导航产状态，就必须填写 `路线证明`

## 七、检查标准

- `总览.md` 顶部使用短摘要块
- `总览.md` 持续使用 `✅ / 🟡 / ⛔ / 🔍 / ➡️`
- `运行态清单.md` 继续只写运行时事实
- `验证记录.md` 明确记录固定输入和路线证明
- 详细验证内容不能只留在 `运行态清单.md`
