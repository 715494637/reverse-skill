# 总览与验证记录

## 一、用途

定位阶段的 `总览.md` 和 `验证记录.md` 要保持紧凑、清楚、归属明确。

本 reference 就是定位阶段这两个文件的唯一权威骨架。

## 二、视觉规则

统一使用纯 Markdown 和少量状态标记：

- `✅ 已确认`
- `🟡 待确认`
- `⛔ 阻塞`
- `🔍 待验证`
- `➡️ 下一步`

同时保留规范状态值，例如 `🟡 待确认（部分完成）`。

## 三、落盘路径

默认写到当前任务工作目录：

```text
reverse-records/
├─ 总览.md
├─ 请求链路.md
├─ 运行态清单.md
├─ 恢复记录.md
└─ 验证记录.md
```

## 六、归属规则

- `总览.md` 负责当前阶段、已确认、待确认、阻塞风险、待验证和下一步
- 正常态 / 风控态对比表和分叉图只能放在 `总览.md`
- `请求链路.md` 负责请求区块、状态数组、`来源/去向`、证据和上游展开
- `验证记录.md` 在 sink 假设、状态链闭合或分叉假设需要证明时开始记录
- `验证记录.md` 可以由 `定位` 提前启动，但归属阶段和完成门禁仍然属于 `验证`

## 七、检查标准

- `总览.md` 顶部使用短摘要块
- `总览.md` 持续使用 `✅ / 🟡 / ⛔ / 🔍 / ➡️`
- 只有存在风控分支时才写分叉图
- `验证记录.md` 使用具体检查点，不能只有最终结论
- 请求结构内容不混进 `总览.md`
