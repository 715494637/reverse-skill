# JSR Runtime

## 概述

当浏览器里链路能走通，但本地执行分叉，真正问题是运行时缺口而不是 sink 不清或算法未恢复时，使用本 skill。

Runtime 完成的标准不是“本地勉强跑通一次”，而是已经说清：

- 浏览器为什么能走通
- 本地为什么分叉
- 哪一组最小依赖能闭合这个缺口

## 自包含规则

- 默认只有这份 `SKILL.md` 会被实际读取。
- 不要因为没打开 `references/` 而停住。
- 下面给出的记录骨架就是权威格式，不依赖其他文件。
- 所有执行记录都直接写入工作目录下的 `reverse-records/`，并且使用中文。
- 不再创建会话子目录；当前任务的记录文件直接在该目录下持续更新。

## 最小输入

开始前先收齐这块输入：

```text

浏览器表现：
本地表现：
当前阻塞或现象：
已知证据：
约束：
```

必填：

- `目标链路或函数`
- `浏览器表现`
- `本地表现`
- `当前阻塞或现象`
- `已知证据`
- `约束`

按需补充：

- `疑似消费点`
- `疑似分叉点`
- `候选运行时路线`
- `已知状态闭合信号`
- `观察到的瑞数特征`
- `观察到的 cookie key 后缀`
- `二跳结果`

## 运行时分类

先把问题分到下面五类之一：

- 缺对象
- 缺状态
- 反调试
- 不稳定源
- 风控分支

不要把它们糊成一句“缺浏览器环境”。

## 核心顺序

1. 先拿到浏览器正常态样本，再补本地运行时。
2. 先找第一个分叉点，并把它归类到五类之一。
3. 如果命中瑞数特征，先判断问题属于 `hasDebug`、`basearr` 闭合、固定运行时事实，还是首跳产状态 / 二跳消费。
4. 在决定走 `sdenv`、远程 jsdom 或任何依赖生命周期产状态的路线前，先做适配检查。
5. 遇到反调试或生命周期陷阱，先选最小匹配规则，不要先放大 patch 范围。
6. 如果状态由生命周期或导航事件产出，只能选一条执行路线：本地回放、远程被动、或远程主动。
7. 在大范围补环境前，先记清注入时机、状态闭合信号和状态载体。
8. 做纯算迁移前置检查：上游响应、`HttpOnly`、一次性 challenge、浏览器内部状态、指纹采集、时间窗 / 序号依赖。
9. 只有前置检查全闭合后，才允许把链路判成可纯算迁移。
10. 对指纹敏感目标，先画 `surface -> collector -> aggregator -> consumer -> 目标字段 / 风控分支`。
11. 先固定时间、随机源和种子，再比较中间值。
12. 瑞数任务里，在 `basearr`、`encryptLens`、`lastWord`、`flag` 和固定运行时事实没验证前，不得宣称闭合。
13. 能补状态时先补状态，再补对象。
14. 每新增一项依赖，都要验证它是否真的改变结果。
15. 如果一条路线会产出供二跳消费的状态，必须做二跳验证后才能接收这条路线。
16. 如果真实难点藏在 `jsvmp`、`worker`、`wasm` 或协议壳里，切 `$jsr-recover`。
17. 如果最终写点还没证明，退回 `$jsr-locate`。

## 交付要求

- 说明当前问题属于哪类运行时问题
- 给出最小运行态清单，而不是模糊大列表
- 说明每个依赖的必要性、证据和可移除性
- 路线选择任务补齐适配检查结论和最终执行模式
- 瑞数任务补齐 `hasDebug`、`basearr`、固定运行时事实和二跳结果
- 如果用了反调试规则，要说明命中表面和最终选中的规则
- 说明当前是否允许纯算迁移；不允许时指出阻塞项
- 给出时间、随机源、状态和输入样本的稳定复现条件

## 失败输出

如果 runtime 停在半路，直接落这个状态块：

```yaml
状态: 就绪 | 部分完成 | 阻塞
阶段: 运行时
代码:
摘要:
证据:
  - ...
影响:
下一动作:
```

- 已经知道问题类别，但关键依赖还没闭合时，用 `部分完成`
- 没有浏览器正常态样本、没有第一个分叉点或无法自洽分类时，用 `阻塞`
- 瑞数任务里，`hasDebug`、`basearr`、固定运行时事实或二跳验证没闭合时，也只能记 `部分完成`
