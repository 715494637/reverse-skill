# 最小运行时设计

## 一、用途

`运行态清单.md` 是当前链路的唯一运行时权威产物。

本 reference 就是 `运行态清单.md` 的唯一骨架。

不要在这里写：

- 完整请求链展开
- 大段恢复结论
- 笼统进度总结

## 二、填写规则

- 从目标链路开始，不要从浏览器对象大列表开始。
- `必需对象` 和 `必需状态` 必须分开写。
- 时间、随机数、种子等固定源必须单独记录。
- 只有当前链路真的受影响时，才写反调试点。
- 只有当前链路真的消费了某个指纹面时，才写指纹归因。
- 只有当前链路真的受风控分支影响时，才写风控分支。
- 只要目标可能适配 `sdenv` 或远程 jsdom，就先写适配检查，再写补项。
- 只要状态由生命周期或导航产出，就必须明确一种执行模式。
- 只要状态由生命周期或导航产出，就必须记录注入时机、状态闭合信号和状态载体。
- 需要高保真浏览器画像时，必须写明选了哪一个画像以及原因。
- 每个依赖项都必须回答 `必要性 / 证据 / 去掉后现象`。

## 四、必须覆盖的区块

`运行态清单.md` 必须能记录下列事实：

- 目标链路、浏览器现象、本地现象
- 适配检查、执行模式、浏览器画像、注入时机、状态闭合信号
- 必需对象
- 必需状态
- 固定源
- 纯算迁移前检查
- 按需反调试
- 按需指纹归因
- 按需风控分支
- 可移除项
- 验证联动

## 五、检查标准

- 运行时产物文件名只能是 `运行态清单.md`，不能再用 `运行时依赖.md`。
- `必需对象` 和 `必需状态` 没有混写。
- 每个依赖项都有 `必要性 / 证据 / 去掉后现象`。
- 任何纯算迁移结论都必须建立在前检查闭合之后。
- 运行时事实继续写在 `运行态清单.md`，不要搬进 `总览.md`。
- 详细验证仍然写在 `验证记录.md`。
