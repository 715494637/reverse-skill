# 请求链路记录

## 一、用途

`请求链路.md` 只记录请求结构、字段状态数组、来源链、上游展开，以及按需记录的连接信息。

以下内容不要写在这里：

- 当前阶段、卡点、下一步、总结论
- 正常态 / 风控态分叉图
- 运行时补项结论
- 恢复层结论或等价性判断

这些内容应写入其他记录文件。

## 二、落盘路径

默认写到当前任务工作目录：

```text
reverse-records/
├─ 会话1/
│  ├─ 总览.md
│  ├─ 请求链路.md
│  ├─ 运行时依赖.md
│  ├─ 恢复记录.md
│  └─ 验证记录.md
├─ 会话2/
│  └─ ...
└─ ...
```

会话规则：

- 一个逆向会话只使用一个 `会话N/` 目录。
- 用户指定了 `会话N`，就只用那个目录。
- 用户未指定时，创建下一个未占用的 `会话N/` 目录。
- 不得覆盖或改写其他 `会话N/` 目录。

## 三、状态标签规范

统一用数组叠加，保留原有状态集合：

- `未知`
- `已知`
- `固定`
- `动态`
- `明文`
- `加密`
- `本地计算`
- `响应获取`
- `环境产生`
- `会话相关`
- `风控相关`
- `时序相关`
- `一次性`
- `可复用`
- `HttpOnly`

示例：

```json
["动态", "响应获取", "HttpOnly", "会话相关"]
```

## 四、写法规则

- 先写目标请求，再展开上游请求。
- 一个请求一个区块。
- 每个请求区块只使用：`请求头`、`Query参数`、`Body参数`、`Cookie`、`响应输出`。
- 每个字段都必须写 `状态`、`来源`、`证据`。
- `状态` 必须使用数组，不写散文式描述。
- `来源` 必须写成 `来源字段 -> 目标字段`。
- 没有上游时写 `上游请求：无`。
- 某个分区没有字段时写 `- 无`。

不要单独再建：

- 依赖总结区
- 当前结论区
- 正常态 / 风控态区

依赖关系已经通过字段级 `来源` 和请求级 `上游请求` 表达。

## 五、请求骨架

```markdown
# 请求链路

## 请求A
- 接口：
- 触发方式：
- 响应结果：
- 上游请求：`请求B`、`请求C`

### 请求头
- `头1`
  - 状态：`["动态","响应获取","会话相关"]`
  - 来源：`请求B.response.token -> 请求A.header.头1`
  - 证据：`发送前对照`

### Query参数
- `参数1`
  - 状态：`["固定","明文"]`
  - 来源：`页面固定值 -> 请求A.query.参数1`
  - 证据：`抓包`

### Body参数
- `参数2`
  - 状态：`["动态","响应获取","一次性"]`
  - 来源：`请求C.response.ticket -> 请求A.body.参数2`
  - 证据：`响应包`

### Cookie
- `cookie1`
  - 状态：`["动态","响应获取","HttpOnly","会话相关"]`
  - 来源：`请求B.Set-Cookie.cookie1 -> 请求A.cookie.cookie1`
  - 证据：`Set-Cookie`

### 响应输出
- `response.field1`
  - 状态：`["动态","响应获取","可复用"]`
  - 去向：`请求D.header.头2`
  - 证据：`响应包`

## 请求B
- 接口：
- 触发方式：
- 响应结果：
- 上游请求：无

### 请求头
- 无

### Query参数
- 无

### Body参数
- `参数1`
  - 状态：`["动态","环境产生"]`
  - 来源：`storage.seed -> 请求B.body.参数1`
  - 证据：`storage 快照`

### Cookie
- 无

### 响应输出
- `response.token`
  - 状态：`["动态","响应获取","会话相关"]`
  - 去向：`请求A.header.头1`
  - 证据：`响应包`
```

## 六、协议 / 长连接补充

遇到 `WebSocket`、`protobuf`、SSE、心跳、续期类任务，保留普通请求区块，并在末尾追加一个可选连接区块。

```markdown
## 连接信息
- 连接：
- 当前状态：
- 会话标识：
- 序号规则：
- ack 规则：
- 续期条件：
```

## 七、检查标准

- 目标请求排在最前。
- 每个字段都有状态数组。
- 每个字段都有具体来源链。
- 每个字段至少有一个证据锚点。
- 上游展开可以通过请求区块直接阅读，不依赖额外总结区。
- 进度、分叉、运行时、恢复结论没有混入本文件。
