# 最小环境设计

## 一、用途

`运行时依赖.md` 只记录当前链路的最小运行时清单。

以下内容不要写在这里：

- 完整请求链展开
- 大段恢复结论
- 通用进度总结

这里只回答当前链路到底需要什么、为什么需要、去掉会发生什么。

## 二、落盘路径

默认写到当前任务工作目录：

```text
reverse-records/
├─ 会话1/
│  ├─ 总览.md
│  ├─ 请求链路.md
│  ├─ 运行时依赖.md
│  ├─ 恢复记录.md
│  └─ 验证记录.md
├─ 会话2/
│  └─ ...
└─ ...
```

会话规则：

- 一个逆向会话只使用一个 `会话N/` 目录。
- 用户指定了 `会话N`，就只用那个目录。
- 用户未指定时，创建下一个未占用的 `会话N/` 目录。
- 不得覆盖或改写其他 `会话N/` 目录。

## 三、写法规则

- 从目标链路开始，不要从浏览器对象大全开始。
- `必需对象` 和 `必需状态` 分开写。
- 时间、随机、种子等固定源必须显式写出。
- 只有影响当前链路的反调试点才记录。
- 只有被消费的指纹表面才记录。
- 只有影响当前链路的风控分支才记录。
- 每一项依赖都要回答 `必要性`、`证据`、`去掉后现象`。

## 五、检查标准

- 对象和状态已经分开。
- 固定源已经明确。
- 纯算迁移前检查已经明确。
- 反调试、指纹、风控分支只在需要时出现。
- 每一项依赖都写明了必要性和证据。
- 详细验证检查点写在 `验证记录.md`，不只停留在本文件。
