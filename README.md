# reverse-skill

面向 Web JS 逆向任务的专业化技能仓库，目标不是提供零散技巧清单，而是把请求定位、运行时诊断、语义恢复三类工作拆成可协作、可验收、可沉淀记录的技能体系。（安卓逆向部分待开发）

## 仓库定位

这个仓库主要解决的不是“会不会找某个 sign 函数”，而是下面这类工程化逆向问题：

- 动态字段、请求头、`cookie`、`HttpOnly` 状态、消息帧到底写在哪、从哪来、依赖哪条上游链路
- 浏览器内可执行、本地环境失败时，真正缺的是对象、状态、时序、指纹面、反调试规避，还是风控分支闭合条件
- 真实业务语义被 `jsvmp`、AST 变换、控制流平坦化、`worker`、`wasm`、`webpack/runtime`、协议包络遮住时，应该恢复到哪一层才足够支撑下游
- 如何把定位结论、运行时结论、恢复结论沉淀为后续可复用的中文记录，而不是每次重新手工梳理

换句话说，这个仓库关注的是“逆向分析链条的组织方式”和“可验证产物的形成方式”，而不是某一个站点、某一种算法、某一段一次性脚本。

## 方法论总览

仓库默认把一条完整逆向链路拆成 3 类核心能力：

- `Locate`：证明目标字段、目标请求、目标消息的真实写边界、来源链、上游依赖链、状态链和正常态 / 风控态分叉关系
- `Runtime`：解释浏览器路径为何成立、本地路径为何分叉，并收敛出最小运行时清单、适配路线与验证要求
- `Recover`：识别遮蔽层，按最低必要恢复级别提炼桥接边界、状态载体、关键算子和等价性检查点

这 3 类能力的顺序不是固定流水线，但存在明确边界：

- 写回点没证明清楚，不应过早进入运行时补环境或语义恢复
- 运行时缺口未分类清楚，不应把所有失败都归因成“环境不完整”
- 遮蔽层未拆开前，不应把“代码变好看”误当成恢复完成

## 设计原则

- 证据优先：结论必须能回指到请求、响应、断点、hook、状态快照或对照验证
- 最小化推进：只恢复当前问题真正需要的那一层，不做无边界扩展
- 阶段分责：定位、运行时、恢复分别回答不同问题，避免单个 skill 同时承担所有任务
- 记录可交接：产物默认写入中文记录，确保后续分析不必重新开链
- 验证闭环：可运行不等于可交付，所有工程化输出都应晚于验证结论

## 使用

按任务类型选择对应 skill：

- `jsr-locate`：用于定位动态字段的写入边界、来源链、请求依赖链、状态链和连接状态链
- `jsr-runtime`：用于诊断对象缺口、状态缺口、反调试、时间随机源、指纹归因与风控分支
- `jsr-recover`：用于恢复 `jsvmp`、`ast`、`worker`、`wasm`、`webpack/runtime`、协议壳等遮蔽层的真实语义

推荐最小输入：

- `(*) URL`
- `接口 / 需要的数据`
- `触发方式`

全自动示例：

```text
使用：JSReverse MCP
方式：在真实浏览器插桩采集完整的输入输出及中间态数据，与本地算法进行逻辑一致性和结果正确性对比分析。
URL: 【https://example.com】
目标：【接口 / 需要的数据】
触发方式: 【刷新页面】
cookie：【使用现有cookie / 如无或者非必要则可以不使用，若必须则需要完整模拟链路生成游客态】
约束：不使用playwright等浏览器自动化工具，不能联网搜索公开案例
必须纯算法实现，【能/不能】依赖补环境
交付：Node.js 生成加密参数，Python 负责调度和发送请求，运行后打印响应数据
```

定向调用示例：

```text
$jsr-locate 梳理请求 A 的写入边界、参数来源、上游依赖和 HttpOnly cookie 链路。
```

```text
$jsr-runtime 判断当前问题属于缺状态、缺对象、反调试还是风控分支，并给出最小环境清单。
```

```text
$jsr-recover 恢复当前 jsvmp + worker + wasm 组合壳，输出桥接边界、关键算子和等价性检查点。
```

## 协作关系

这三类 skill 不是平行的“功能菜单”，而是互相切换的分析阶段：

- 当目标是请求字段、请求头、`cookie`、消息对象的真实写入关系时，先用 `jsr-locate`
- 当写入点已知，但浏览器与本地结果不一致，或一调试就进入不同路径时，切 `jsr-runtime`
- 当链路已知，但真实语义被壳层、调度层、桥接层遮蔽时，切 `jsr-recover`

典型切换方式：

- `Locate -> Runtime`：写点已知，但值依赖页面生命周期、浏览器状态、指纹面或反调试条件
- `Locate -> Recover`：写点或 builder 已接近，但中间逻辑被 `jsvmp`、`worker`、`wasm`、协议壳遮蔽
- `Runtime -> Recover`：已经确认不是简单缺对象或缺状态，而是壳层内逻辑未恢复
- `Recover -> Locate / Runtime`：恢复出了桥接边界、状态载体或关键算子后，回到链路证明或运行时验证

## 产物与验收

仓库强调“阶段产物可验收”，而不是“过程讲得通”。核心验收物通常包括：

- `jsr-locate`：写边界、`entry -> builder -> writer` 关系、上游依赖链、状态链、正常态 / 风控态分叉结论
- `jsr-runtime`：最小运行时清单、适配检查、执行模式、纯算迁移前检查、可移除项、验证联动要求
- `jsr-recover`：遮蔽层类型、恢复级别、停止理由、桥接契约、状态载体、关键函数卡片、等价性检查点

在这套仓库里，下面这些都不算完成：

- 只找到可疑函数，但没有证明它就是最终写边界
- 只让代码跑起来一次，但没有说明哪些依赖真正必要
- 只把混淆代码格式化了，但没有恢复桥接边界和关键语义
- 只得到“结果一样”，但没有对中间检查点做对照验证

## 技能概览

### `jsr-locate`

核心职责：

- 定位目标字段的最终写入边界
- 建立 `entry -> builder -> writer` 关系
- 证明参数、请求头、`cookie`、`HttpOnly cookie`、消息字段的来源
- 展开前置请求、响应依赖、状态链、正常态 / 风控态分叉
- 处理 `WebSocket`、`protobuf`、长连接场景下的连接状态链与消息族定位

典型进入条件：

- 不清楚 `sign`、`token`、`cookie`、请求头、请求体字段从何处写入
- 已知目标请求，但不清楚其依赖的前置请求、响应字段或状态
- 需要将链路展开到可获得正常响应的闭合状态

### `jsr-runtime`

核心职责：

- 区分对象缺失、状态缺失、反调试、不确定源、风控分支
- 设计最小环境并说明每项依赖的必要性
- 固定时间源、随机源、种子与会话状态
- 建立纯算迁移前检查与指纹归因矩阵
- 识别正常态 / 风控态分叉点与运行时消费点

典型进入条件：

- 浏览器内正常，本地执行异常
- 调试后值变化、执行卡死、链路跳入风控分支
- 不清楚问题属于环境对象、会话状态、指纹消费还是风险校验

### `jsr-recover`

核心职责：

- 判定遮蔽层类型与最低必要恢复级别
- 恢复 `jsvmp`、`ast`、控制流平坦化、`worker`、`wasm`、`webpack/runtime`、协议壳
- 提取桥接契约、状态载体、关键算子、模块闭包边界
- 支持协议包络、消息族、长连接状态迁移分析
- 输出等价性检查点与可复用的恢复记录

典型进入条件：

- 已定位写回边界，但中间语义被多层壳遮蔽
- 需要先恢复桥接层、调度层或状态载体，才能继续定位或复现
- 需要判断当前任务应停留在 `A / B / C` 哪一级恢复深度

## 工作目录记录

执行三类 skill 时，默认在当前任务工作目录维护中文记录。记录文件不是附属说明，而是后续切换 skill、回放验证、沉淀结论的主载体：

```text
<当前任务工作目录>/reverse-records/
├─ 会话1/
│  ├─ 总览.md
│  ├─ 请求链路.md
│  ├─ 运行态清单.md
│  ├─ 恢复记录.md
│  └─ 验证记录.md
├─ 会话2/
│  ├─ 总览.md
│  ├─ 请求链路.md
│  ├─ 运行态清单.md
│  ├─ 恢复记录.md
│  └─ 验证记录.md
└─ ...
```

文件职责：

- `总览.md`：记录当前阶段、已确认内容、当前卡点、下一步、风险和待验证事项
- `请求链路.md`：记录请求区块、字段状态数组、来源 / 去向、上游展开和连接状态
- `运行态清单.md`：记录最小运行时清单、执行模式、纯算迁移前检查和可移除项
- `恢复记录.md`：记录遮蔽层、恢复级别、桥接契约、状态载体和关键函数卡片
- `验证记录.md`：记录固定输入、检查点、对照结果、差异定位和验证结论

记录规则：

- 一个逆向会话只使用一个 `会话N/` 目录
- 用户指定 `会话N` 时，只读取和写入该目录
- 用户未指定时，创建下一个未占用的 `会话N` 并只写入该目录
- 不得覆盖、合并、重命名、清理其他 `会话N/` 目录中的记录
- 协议 / 长连接状态写入当前会话 `请求链路.md` 的专门章节，不再单独创建 `协议状态.md`
- 文件不存在时按需创建，存在时仅更新当前会话中的对应文件
- 每次推进后至少更新一次当前会话 `总览.md`
- 涉及接口复现、状态链、连接状态链时优先更新当前会话 `请求链路.md`

## 适用与边界

适用：

- Web 端动态参数、登录链路、挑战链路、指纹链路、风控链路分析
- 请求重放前的来源证明、状态证明、依赖闭合和运行时闭合
- `jsvmp`、AST、`worker`、`wasm`、`webpack/runtime`、协议封装等典型遮蔽层恢复

不直接解决：

- 面向单站点的成品脚本交付仓库管理
- 浏览器自动化采集框架本身的封装
- 安卓 Native / ART / so 逆向的完整流程

## 目标读者

这个仓库更适合下面几类人：

- 需要把 Web 逆向任务拆成稳定分析步骤的 AI 使用者
- 希望让 Codex / Claude 在定位、运行时、恢复之间更少乱跳的使用者
- 需要沉淀中文逆向记录、后续还能继续接力的团队或个人
