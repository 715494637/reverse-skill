# 等价性验证与恢复记录

## 一、用途

恢复与验证内容统一写入 `请求链路.md` 的 `恢复补充` 与 `验证补充` 小节。

它们应该保持紧凑、结构化、可证明，不要写成长篇说明。

不要混入完整请求链展开、运行时清单或笼统阶段总结。

## 二、视觉规则

统一使用纯 Markdown 和少量状态标记：

- `✅ 已确认`
- `🟡 待确认`
- `⛔ 阻塞`
- `🔍 待验证`
- `➡️ 下一步`

## 三、落盘路径

默认写到当前任务工作目录：

```text
reverse-records/
└─ 请求链路.md
```

## 四、写法规则

- `恢复补充` 负责层级卡片、边界卡片、恢复级别、停止理由、状态载体和关键函数卡片
- `验证补充` 负责检查点、固定输入、等价结果和剩余缺口
- 检查点必须具体，不能只比较最终输出
- 层级名称必须明确：`外层容器`、`调度层`、`状态载体`、`桥接层`、`核心算子`、`写回层`
- 每张关键函数卡片都必须写 `输入 / 输出 / 副作用 / 依赖 / 证据`

## 六、等价性要求

每次等价性验证都必须回答：

- 固定了哪个输入样本
- 当前比对的是哪个检查点
- 如果只是部分等价，剩余缺口在哪里
- 哪条证据证明的是当前检查点，而不是只证明最终输出

常见检查点包括：

- 桥接契约输入与输出
- 提炼算子的输入与输出
- 调度器或状态载体的状态转移
- 写回前的中间结果

## 七、检查标准

- 恢复相关产物里不再使用旧文件名 `运行时依赖.md`
- 恢复结构和验证证明保持分离
- 检查点足够具体，能够指出等价失败的位置
- 非恢复内容没有混进这些补充小节
