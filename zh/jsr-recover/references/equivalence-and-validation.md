# 等价性验证与恢复记录

## 一、用途

`恢复记录.md` 和 `验证记录.md` 只记录恢复结构与验证证明。

本 reference 就是 `恢复记录.md` 的唯一权威骨架，并补充恢复阶段的等价性规则和检查点要求。

不要在这里写：

- 完整请求链展开
- 最小运行时清单
- 通用进度总结

## 二、落盘路径

默认写到当前任务工作目录：

```text
reverse-records/
├─ 会话1/
│  ├─ 总览.md
│  ├─ 请求链路.md
│  ├─ 运行态清单.md
│  ├─ 恢复记录.md
│  └─ 验证记录.md
├─ 会话2/
│  └─ ...
└─ ...
```

## 三、写法规则

- `恢复记录.md` 记录层级卡片、边界卡片、恢复级别、停止理由、状态载体和关键函数卡片。
- `验证记录.md` 记录检查点、固定输入、等价结果和缺口位置。
- 检查点必须具体，不能只比较最终输出。
- 层级名称必须明确：`外层容器`、`调度层`、`状态载体`、`桥接层`、`核心算子`、`写回层`。
- 每张关键函数卡片都必须写 `输入 / 输出 / 副作用 / 依赖 / 证据`。

## 四、恢复骨架

```markdown
# 恢复记录

- 样本编号：
- 证据编号：
- 遮蔽层类型：
- 恢复级别：A级 / B级 / C级
- 停止理由：
- 入口锚点：
- 语义边界：
- 桥接契约：
- 状态载体：
- 关键数据结构：
- 关键函数卡片：
- 协议语义：
- 已确认映射：
- 未恢复缺口：
- 下一恢复点：
```
## 五、等价性要求

每次等价性验证都必须回答：

- 固定了哪个输入样本
- 当前比对的是哪个检查点
- 若只是部分等价，剩余缺口在哪里
- 哪条证据证明当前检查点，而不是只证明最终输出

常见检查点包括：

- 桥接契约输入与输出
- 提炼算子的输入与输出
- 调度器或状态载体的状态转移
- 写回前的中间结果

## 六、检查标准

- 恢复相关产物里不再使用旧文件名 `运行时依赖.md`
- 恢复结构和验证证明已经分离
- 检查点足够具体，能够指出等价失败的位置
- 非恢复内容没有混进这些文件
