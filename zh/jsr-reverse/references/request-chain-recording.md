# 请求链路记录

## 一、用途

`请求链路.md` 是请求结构记录的唯一权威产物，目标是紧凑、好扫读、少废话。

这里只记录：

- 请求区块
- 字段状态数组
- 来源 / 去向证明
- 上游展开
- 按需连接信息

不要把阶段总结、运行时决策或恢复结论混进请求区块正文。若必须交接这些内容，只在文末追加紧凑补充小节。

## 二、视觉规则

统一使用纯 Markdown 和少量状态标记：

- `✅ 已确认`：已证明
- `🟡 待确认`：还有闭环缺口
- `⛔ 阻塞`：缺前置条件
- `🔍 待验证`：需要在当前文件的 `验证补充` 小节标出缺口

## 三、落盘路径

默认写到当前任务工作目录：

```text
reverse-records/
└─ 请求链路.md
```

当前任务使用一个扁平的 `reverse-records/` 目录，并持续更新这一个文件。

## 四、状态标签标准

`状态` 必须继续使用数组，并保留下列标签：

- `未知`
- `已知`
- `固定`
- `动态`
- `明文`
- `加密`
- `本地计算`
- `响应获取`
- `环境产生`
- `会话相关`
- `风控相关`
- `时序相关`
- `一次性`
- `可复用`
- `HttpOnly`

示例：

```json
["动态", "响应获取", "HttpOnly", "会话相关"]
```

## 五、文件头

`请求链路.md` 顶部统一用短摘要块：

```markdown
# 请求链路

- 目标请求：
- 目标对象：
- 当前样本状态：🟡 待确认（正常态 / 风控态 / 未知）
- 关键未闭环：
- 样本编号：
- 证据编号：
```

## 六、填写规则

- 目标请求必须排第一
- 上游请求紧跟目标请求逐层展开
- 一个请求区块只写一个请求
- 请求摘要统一用紧凑表格
- 字段区统一用紧凑表格
- 请求输入字段使用 `状态 / 来源 / 证据`
- 响应输出字段使用 `状态 / 去向 / 证据`
- 某个区块没有字段时写 `- 无`
- 没有上游请求时写 `无`

如需补充依赖总结、当前进度或最终结论，只在文末追加紧凑补充小节。

## 七、请求区块骨架

```markdown
## 请求A｜目标请求

| 项目 | 内容 |
|---|---|
| 接口 |  |
| 触发方式 |  |
| 上游请求 | `请求B`、`请求C` / 无 |
| 响应结果 |  |

### 请求头
| 字段 | 状态 | 来源 | 证据 |
|---|---|---|---|
| `头1` | `["动态","响应获取","会话相关"]` | `请求B.response.token -> 请求A.header.头1` | `发送前对照` |

### Query 参数
| 字段 | 状态 | 来源 | 证据 |
|---|---|---|---|
| `参数1` | `["固定","明文"]` | `页面固定值 -> 请求A.query.参数1` | `抓包` |

### Body 参数
| 字段 | 状态 | 来源 | 证据 |
|---|---|---|---|
| `参数2` | `["动态","响应获取","一次性"]` | `请求C.response.ticket -> 请求A.body.参数2` | `响应包` |

### Cookie
| 字段 | 状态 | 来源 | 证据 |
|---|---|---|---|
| `cookie1` | `["动态","响应获取","HttpOnly","会话相关"]` | `请求B.Set-Cookie.cookie1 -> 请求A.cookie.cookie1` | `Set-Cookie` |

### 响应输出
| 字段 | 状态 | 去向 | 证据 |
|---|---|---|---|
| `response.field1` | `["动态","响应获取","可复用"]` | `请求A.response.field1 -> 请求D.header.头2` | `响应包` |
```

## 九、阶段补充（按需）

当前版本只写 `请求链路.md` 时，把阶段交接压缩成文末补充小节：

```markdown
## 运行时补充
- 当前分叉：
- 必需对象 / 状态：
- 下一步：

## 恢复补充
- 当前边界：
- 已确认契约：
- 未恢复缺口：

## 验证补充
- 当前检查点：
- 已确认结论：
- 剩余证据缺口：
```

## 十、检查标准

- 目标请求排在最前
- 每个字段都有状态数组
- 每个字段都有具体来源链或下游目标
- 每个字段至少有一个证据锚点
- 不加总结散文也能读清上游展开
- 进度、分叉、运行时、恢复内容若必须出现，也只以紧凑补充小节出现，不展开成长文
