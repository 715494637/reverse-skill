# 总览与验证记录

## 一、用途

恢复阶段的 `总览.md` 和 `验证记录.md` 要保持紧凑、清楚、归属明确。

本 reference 就是恢复阶段这两个文件的唯一权威骨架。

## 二、视觉规则

统一使用纯 Markdown 和少量状态标记：

- `✅ 已确认`
- `🟡 待确认`
- `⛔ 阻塞`
- `🔍 待验证`
- `➡️ 下一步`

同时保留规范状态值，例如 `🟡 待确认（部分完成）`。

## 三、落盘路径

默认写到当前任务工作目录：

```text
reverse-records/
├─ 会话1/
│  ├─ 总览.md
│  ├─ 请求链路.md
│  ├─ 运行态清单.md
│  ├─ 恢复记录.md
│  └─ 验证记录.md
├─ 会话2/
│  └─ ...
└─ ...
```

## 六、归属规则

- `总览.md` 负责当前阶段、已确认、待确认、阻塞风险、待验证和下一步
- `恢复记录.md` 负责层级卡片、桥接卡片、状态载体、恢复级别、停止理由和关键函数卡片
- `验证记录.md` 在等价性工作或固定输入检查开始时进入记录
- `验证记录.md` 可以由 `恢复` 提前启动，但归属阶段和完成门禁仍然属于 `验证`
- 验证目标继续限定为恢复级别证明、桥接证明和等价性检查点

## 七、检查标准

- `总览.md` 顶部使用短摘要块
- `总览.md` 持续使用 `✅ / 🟡 / ⛔ / 🔍 / ➡️`
- `恢复记录.md` 保持结构化，并说明为什么能停在当前恢复级别
- `验证记录.md` 使用具体检查点，并明确剩余缺口
